# MyGo 技术验证与产品约束

日期：2026-10-20。平台：macOS 26.5 / Apple Silicon。验证框架固定为
`github.com/egoist/mygo v0.5.6-0.20261020063447-d5bcfdb3d75b`
（commit `d5bcfdb3d75bfc0609f2866be227e73dc45391dd`），Go 1.27.1，
`CGO_ENABLED=0`。

## 当前结论

**MyGo 可承担本产品的窗口、菜单栏、全局唤起、剪贴板多格式读写与增强结果界面。**
剪贴板版本、目标应用识别和选择性按键阻止，需补一个小型 macOS 原生层。

现阶段已完成纯 Go 原型、桌面集成和两轮真实键盘验证。本轮用户确认：
在 TextEdit 按 `⌃⌘C` 出现保护成功提示，来源应用内 `⌘V` 正常，
其他应用中粘贴被阻止并出现提示；面板记录了实际来源、范围及 ChatGPT 阻止事件。
上一轮还验证了受限增强 JSON 在系统设置搜索框中被真实 `⌘V` 阻止。

这足以确认“保护复制 → 来源范围 → 同源放行 / 跨应用阻止”以及
“内容增强 → 继承范围 → 真实键盘误贴被阻止”的可行性，
但不等于所有粘贴方式、应用或非激活面板的焦点行为已经全面通过。

## 证据与未完成项

### 新增：⌃⌘C 来源限定复制

已接入现有 MyGo 原型。开启守卫后，原生 tap 把同一次 C 按键的 Control 修饰位
去掉，让前台来源应用处理普通 `⌘C`；不额外发送键盘事件。记录触发时的来源、
基准版本及请求 ID，在最多 2 秒内读取非空文本（上限 1 MiB）及其富文本表示。
校验来源未切换、版本稳定、请求仍有效、守卫仍开启后，原子绑定来源应用范围，
再记录历史并给出不抢焦点的短提示。

已完成的代码验证：

- 主流程测试：新版本确认前不改历史；无新内容不误锁旧项；来源 PID / Bundle ID
  改变时取消；暂未就绪的内容可重试；读取期间版本变化或原生确认失败不入库；
  文本大小边界；确认后外部覆盖保留受限历史但取消“当前”；原多格式内容保留。
- 原生状态 / 内存 CGEvent 测试：精确组合键、C 的按下与抬起配对、长按抑制、
  请求替换与超时、普通复制 / 剪切及其他输入取消、面板焦点取消、
  待确认时跨应用粘贴阻止、确认与新请求的原子顺序。
- 历史模型测试：保护记录一次建立；普通重新复制相同文本仍是独立无限制记录；
  历史选用和增强结果继续保留原范围。
- 三个包 `go test ./...` 及 `go vet ./...` 通过；构建为 `CGO_ENABLED=0`。

本轮还修复了普通诊断窗口在后台可见时被错误豁免的问题，改为按焦点排除自身。
成功反馈绑定剪贴板版本和当前规则；普通复制、解除规则或关闭守卫后撤下。
暂停普通历史监听不会拒绝用户主动触发的 `⌃⌘C`。

**TextEdit 来源的核心流程已通过真实键盘验收。** 用户确认 `⌃⌘C` 出现成功提示，
TextEdit 内粘贴成功，其他应用粘贴失败且出现提示。随后桌面工具核对：
合成文本 `Copiggy-SourceOnly-20261020` 新增了两条历史，实际来源均为文本编辑，
范围均为“仅限文本编辑”，最新一条标为当前剪贴板；末条状态是
“已阻止粘贴到 ChatGPT：此内容设有应用限制”。成功提示和同源插入由用户实测报告，
历史属性和具体阻止目标由应用控件状态佐证，没有把两条记录推断为长按或重复触发。

工具随后用普通 `⌘C` 复制相同文本，受限历史仍保留，旧记录的“当前剪贴板”标记
消失，符合版本替换规则。普通历史监听始终暂停，因此不为这次普通复制新增历史。
这项检查仅验证实际复制后的模型状态；没有将工具模拟粘贴视作物理键盘放行证据。
无选区、快速切换和复制失败已通过代码测试，本轮未再做这些分支的物理键盘复测。

桌面工具的 `ctrl+super+c` 未产生保护复制事件，而用户真实按键产生了事件；
继续保留模拟路径与真实键盘的区别。当前构建已刷新原有辅助功能授权。
本轮结束时守卫开启、普通监听暂停，当前内容为普通复制的合成文本。

### 真实按键的验收标准

实测只使用合成 JSON 和空白输入框，不发送消息、不提交网页。

1. 启用防误贴，选用仅允许 TextEdit 的示例，在 TextEdit 空白文档中按 `⌘V`，内容正常插入。
2. 同一剪贴板内容在不允许的应用输入框中按 `⌘V`，内容不插入；面板出现对应应用的阻止信息。
3. 停止防误贴，在第二步的同一输入框中按 `⌘V`，内容正常插入。
   这项对照排除“输入框未聚焦 / 快捷键未送达”造成的假通过。
4. 再启用防误贴，检查 `⌘⌥⇧V`、增强结果的范围继承，以及外部新复制后旧规则解除。

最终实际覆盖：步骤 1 使用桌面工具按键，步骤 2 使用用户物理按键并核对应用事件，
第 4 步的增强范围继承也在这次物理阻止中得到验证。尚未要求用户进行步骤 3 的
物理按键对照，以及匹配样式和外部新复制的物理按键测试。

### 交互验证中发现的差异

- 非激活菜单栏面板无法被本轮桌面工具稳定连接，因此增加普通诊断窗口模式，
  默认启动该模式；`--panel` 保留原非激活面板。普通窗口不是最终产品设计。
- 重编译改变本地签名，系统保留的旧条目曾显示开启，而当前应用仍报告未授权。
  经用户授权，通过系统设置移除旧 Copiggy 条目、添加当前 `.app` 后，实际守卫
  才成功运行。命令行启动的 `--probe` 结果不能单独证明桌面启动进程的权限。
- 上一轮普通诊断窗口曾沿用“窗口可见即豁免”规则，当时测试前已收起窗口。
  本轮已修复为按实际焦点排除自身，不再因诊断窗口在后台可见而豁免其他应用。
- 桌面工具模拟按键没有触发阻止，用户真实键盘触发了阻止。Apple SDK 区分
  按 PID 投递与按 session 位置投递，但未取得工具实现，**不声称已经证明工具使用了某个 API**。
- 上一轮验证结束时停止守卫、历史监听关闭，剪贴板为合成增强 JSON；
  本轮的最终运行状态见上方“⌃⌘C 来源限定复制”。

## 实现分工

- MyGo：`Clipboard.Read/Write/Flush`、`transfer.Data`、`WindowOptions.Panel`、
  `NewTray`、`GlobalShortcut.Register`、原生 UI、后台结果回到主线程。
- macOS bridge（purego）：`NSPasteboard.changeCount`、`NSWorkspace`、
  `NSRunningApplication`、`CGEventTap`、权限状态和生命周期。
- 内容模型：内存历史、明确选用、不可变增强草稿、取消与失败、继承应用范围。
- 未来 AI adapter：只在用户主动操作时发送所选内容，结果仍然经过同一草稿确认流程。

不使用 MyGo 的全局快捷键注册接管 `⌘V`。该 API 用于唤起；条件放行需要主动事件 tap。
允许时原样返回事件，禁止时丢弃，不模拟一次新的粘贴。

## 验证发现

1. **`Flush` 自身会更新剪贴板版本。** 版本绑定应在 Flush 完成之后建立。
   自测使用独立随机标记确认版本属于本次写入，不能把 Flush 的新版本误判为用户复制。
2. **富文本应显式提供正确纯文本表示。** MyGo `WriteHTML` 的纯文本 fallback
   是 HTML 字符串；这里使用 `transfer.NewItem(Text, HTML)`，避免粘出标签。
3. **非激活 Panel 可以保持原应用身份。** 但在面板输入时，事件 tap 不能仅按
   `frontmostApplication` 判断目标，因此排除本进程 / 面板输入；有事件目标 PID
   时优先按 PID 识别。
4. **规则绑定实际剪贴板版本。** 不以“最近选中的历史条目”或“文本相等”
   代替版本。外部新复制立即解除旧版本规则。
5. **确认草稿前必须再次检查源规则。** 如果增强期间改变了允许范围，旧草稿
   拒绝确认，要求重新生成；不能靠修改 UI 返回的数据来放宽权限。
6. **空格应留给搜索输入。** 技术原型用 `⌘P` 预览。正式设计如果采用空格
   Quick Look，需要清楚区分列表焦点与输入框焦点。

### 自测恢复问题记录

首次原生自测错误地认为 Flush 前后版本应相同，因此将其误判为外部写入，
跳过了恢复，留下合成测试文本，**首次自测前的原剪贴板未恢复**。
已向用户说明。修复后以独立标记确认 Flush 写入，并通过再次实测验证：
恢复原始 item 边界、原生类型及字节。第二次恢复成功仅说明恢复到第二次测试前
的内容，不能声称追回第一次丢失的剪贴板内容。

备份仅在内存，读取失败或超过 16 MiB 时不开始写测试数据；
发现用户产生了更新复制则不覆盖。系统 pasteboard 没有原子的 compare-and-swap，
这仍是受控测试辅助，不是可无条件覆盖并发操作的事务保证。

## 据此调整产品设计

产品主线是 **选择内容 → 按需增强 → 设为当前剪贴板 → 用户自己 ⌘V**。

- 默认面板：搜索、历史记录、“当前”标记和简短范围标记。移除“粘贴到”与粘贴按钮。
- 操作入口：选中内容后，通过轻量的“处理”菜单或 `⌘K` 打开相关增强；
  避免把翻译、改写、清理、格式化等按钮全部铺在主面板上。
- 增强预览：先显示结果，可查看原文；回车“使用结果”，Esc 放弃。
  等待、失败、取消都不改变当前剪贴板。原文保留，结果单独入历史。
- 本地增强与 AI 共用确认流程，但应明确是否会联网；没有配置 AI 时不假装已可使用。
- 防误贴：在真实粘贴按键时给短暂提示。权限未开时明确显示“未开启”，不能显示保护中。
- 同一条内容的原文、纯文本转换和增强结果沿用相同的应用范围。

当前原型为技术诊断用途，按钮较多，不代表最终面板布局。下一轮视觉设计应在
上述事实基础上压缩成“历史 / 处理菜单 / 增强预览”，把权限管理放入设置，
把误贴反馈留在粘贴发生的位置。
