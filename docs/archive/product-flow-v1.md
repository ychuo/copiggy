# Copiggy：技术验证后的产品流程

本稿是产品行为设计，尚未实现为最终界面。技术证据见
[MyGo 验证报告](mygo-feasibility-2026-10-20.md)。

## 核心约定

**复制 → 找到记录 → 按需增强 → 设为当前剪贴板 → 用户自行 ⌘V。**

浏览、搜索、预览都不改当前剪贴板。回车明确选用并收起面板；界面没有“粘贴”
或“粘贴到某个应用”按钮。应用范围限制在用户实际按粘贴快捷键时判断，
不阻止用户查找、预览和加工自己的内容。

## 保护复制：⌃⌘C（原型已接入）

开启防误贴后，以复制动作直接决定这条内容的使用范围：

| 操作 | 结果 |
|---|---|
| `⌘C` | 普通复制，成功产生的新记录不附加应用限制 |
| `⌃⌘C`（Control + Command + C） | 保护复制：复制选中内容，并将这条内容限定在来源应用中用标准粘贴快捷键使用 |
| `⌘V` | 保持原操作；仅对当前受限内容检查目标应用 |

普通 `⌘C` 不增加连击识别或等待。保护复制是独立、明确的一次操作；
工具需要让来源应用执行一次正常复制，确认取得本次内容后绑定范围。成功后短暂显示
“已保护 · 仅限文本编辑”，不打开面板、不弹确认对话框。

同一条历史记录重新选用、转换格式或增强后，仍保留这个范围。下一次普通复制
成功时，新内容没有该限制；旧历史记录的限制不被清除。普通复制失败时也不能
解除当前旧内容已有的限制。

### 快捷键取舍

| 候选 | 决策 |
|---|---|
| `⌃⌘C` | 推荐先作为默认；保留 C 的复制含义，额外 Control 表达主动保护，不依赖连击速度 |
| 连按 `⌘C、C` | 不作为首版入口；与用户反复复制确认成功的习惯难以区分 |
| `⌥⌘C` | 不选默认；macOS 文本编辑已有“复制样式”等用途 |
| `⇧⌘C` | 不选默认；Finder 打开“电脑”，VS Code 打开外部终端 |
| 先复制、再按另一快捷键加限制 | 不选主流程；多一个步骤且更容易漏保护 |

只提供一个默认保护复制快捷键，在设置中允许修改，不向首次用户展示多套模式。
不声称 `⌃⌘C` 在所有应用里没有冲突；默认值仍需在目标应用和不同键盘上检查
冲突、单手可达性及复制兼容性。全局注册成功也不能证明没有覆盖应用自身的快捷键。

保护复制不兼作解除保护：解除限制通过记录的范围菜单完成。当前原型只有防误贴
开启后才接管此组合键；未开启时，面板显示“启用防误贴”，组合键仍由原应用处理，
不承诺执行复制，也不会显示受保护。正式版若要在权限缺失时响应全局操作，
需要额外设计快捷键注册与权限提示，不能依赖已经停用的事件监听。

已核对的一手快捷键资料：
[Apple Mac 快捷键](https://support.apple.com/en-us/102650)、
[VS Code 默认快捷键](https://code.visualstudio.com/docs/reference/default-keybindings)。

### 实现时不能省略的确认

以触发时的来源应用身份和复制前的剪贴板版本建立候选记录，
只有观测到新版本、读到有效文本且来源仍在前台，才能绑定规则并提示成功。
来源应用尚未写入新内容时，进入短暂的待确认状态；
不能仅靠当前 300ms 的历史轮询，也不能先把旧版本锁上。

待确认期间的粘贴按键要明确处理为“保护尚未就绪”，不能让用户误认为已经受保护。
没有新内容、无法确认归属、期间切换应用或出现冲突版本时，取消本次保护请求，
提示“未能确认保护复制”，保留原有记录规则。不要用文本相同推断复制归属。

原型通过原生事件 tap 去掉本次 C 按键的 Control 修饰位，使来源应用收到一次
普通 `⌘C`；不合成新的复制或粘贴按键。匹配的抬键也去掉 Control，长按重复事件
不再产生额外复制。主线程读取新内容后，以请求 ID、来源 PID / Bundle ID、
剪贴板版本和 2 秒期限重新校验，再原子绑定规则并存入历史。

普通复制 / 剪切、其他输入、面板获得焦点、选用历史或停止守卫会取消待确认请求。
成功提示绑定当前版本与保护状态；后来普通复制或关闭守卫时撤下，避免过时提示。
用户明确触发的保护复制在“历史监听暂停”时仍会记录；后台普通复制仍不记录。
当前原型支持不超过 1 MiB 的非空文本及其富文本表示，纯图片不报告保护成功。

系统共享剪贴板没有可靠的写入者身份；“前台来源 + 新版本”是尽力关联，不能证明
没有后台程序同时写入。本轮已通过 TextEdit 来源的真实键盘核心流程：
`⌃⌘C` 成功提示、同源粘贴成功、跨应用粘贴阻止，面板记录的阻止目标为 ChatGPT。
其他编辑器兼容性和快速切换等边界仍需逐项实测；进程内事件测试不等于实机覆盖。

这个范围按应用划分：Chrome 的不同标签页仍属于同一应用，聊天应用内的
不同联系人也一样。产品承诺继续限定为键盘防误贴，不能描述成“其他应用绝对读不到”。

## 面板的四种基础状态

| 状态 | 主体 | 操作与反馈 |
|---|---|---|
| 默认 | 最近记录、搜索框；标记当前剪贴板 | 单击和方向键只选择；回车选用并收起 |
| 搜索 | 原位置显示筛选后的列表 | 相同的选择与回车行为；无结果时回车无动作 |
| 预览 | 在同一面板阅读完整内容 | 回车选用；返回列表；通过单一“增强”入口处理内容 |
| 受限 | 在记录和预览上附加“仅限：文本编辑”等范围标记 | 仍可正常选用；错误应用中真实按 ⌘V 才出现短提示 |

“受限”是内容属性，不另建一张禁止选用的页面，也不把面板打开前的应用当成
固定粘贴目标。权限关闭时应明确“防误贴未开启”，而不是仅显示一个让人误以为
已受保护的锁图标。

预览快捷键暂用 `⌘P`。搜索框中的空格仍用于输入；若未来采用空格预览，
必须先定义清楚搜索框与列表的焦点切换。

## 内容增强是同一个面板的下一步

选中内容 → 打开“增强”菜单 → 选择相关操作 → 检查结果 → 回车使用结果。

首版菜单保持少量且与内容相关：

- **清理空白**：处理多余空行、行尾空白等。真实本地操作已验证。
- **格式化 JSON**：仅在内容可以解析为 JSON 时提供。真实本地操作已验证。
- **翻译、精简**：作为后续 AI 操作，仍放在这个菜单，不增加聊天页面。
  当前未配置 AI 服务，不把它们呈现为已经可用。

结果预览默认展示结果，提供轻量“查看原文”；不默认挤成两个狭窄并排区域。
回车文案为“使用结果”，含义始终是写入剪贴板，之后由用户自己粘贴。

## 必须一致的状态规则

| 情况 | 行为 |
|---|---|
| 正在处理 | 当前剪贴板不变，允许取消 |
| 用户取消 | 丢弃草稿，原文和当前剪贴板不变 |
| 处理失败 | 在当前面板说明原因；不生成空历史记录，不替换原文 |
| 处理时用户又复制 | 新复制立即成为当前；稍后完成的增强仍只是草稿 |
| 确认结果 | 验证草稿有效、写入成功后，结果独立入历史；原文保留 |
| 内容有应用范围 | 增强结果继承相同范围，AI 不能自行放宽 |
| 处理时原文范围改变 | 拒绝旧草稿确认，重新处理，避免沿用过期范围 |
| 系统权限或守卫失效 | 明确显示防误贴未生效；历史管理和本地增强继续可用 |

AI 只处理用户主动选中的内容；首次使用时说明服务和联网处理范围。历史搜索
与本地增强不依赖 AI。模型返回后也必须经过同一个结果预览和明确选用流程。

## 菜单栏

菜单栏保留“打开面板、暂停记录、设置、退出”和必要的状态反馈。日常找内容与
增强集中在面板内，不在两个入口重复铺开全部功能。

## 首版边界

防误贴承诺限定为标准键盘粘贴快捷键。菜单 / 右键粘贴、后台读剪贴板、同一
应用里的错误联系人不在当前机制的覆盖范围。面板外即时提示已在保护复制原型接入；
正式应用选择器、历史持久化、纯图片历史界面和 AI 服务仍需后续实现。
