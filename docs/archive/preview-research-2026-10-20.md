# Copiggy 预览区调研与调整

日期：2026-10-20。研究范围为官方产品说明与 Apple 指南，不把竞品文档当作其全部界面的实测记录。

## 当前问题

用户提供的截图中，右侧依次出现 `JSON` 标题、处理图标、关闭图标、范围说明，最后才是内容。
重复类型、独立的控制行和靠前的状态行把右侧组织成了一个“小页面”，与以历史内容为主的左侧脱节。
仅去掉分割线不能解决这种层级问题。用户进一步确认：纯文本不需要操作区。
随后用户明确要求各类型共用“上方内容、下方信息与操作”的结构。本稿据此更新：
撤销早期“操作紧跟正文”和“图片角落放大”的摆放建议，改为固定在预览底部的统一区域；
纯文本仍不增加操作按钮，只显示信息。

## 官方事实与设计推论

| 来源 | 官方资料确认的事实 | 对本项目的设计推论 |
|---|---|---|
| [Raycast Clipboard History](https://manual.raycast.com/clipboard-history) | 选中历史后可用 `⌘K` 打开附加动作面板；Return 的主动作可设为复制回剪贴板。 | 查看内容与附加动作可以分层；取用不必与自动粘贴绑定。 |
| [Paste on Mac](https://pasteapp.io/help/paste-on-mac) | 选中条目先预览；Space 打开完整 Quick Look；`⌘E` 或上下文菜单进入编辑；图片可使用相关快速动作。 | 预览首先用于确认内容，编辑是后续状态。操作随内容类型变化，但可使用一致的位置。 |
| [Maccy 官方 README](https://github.com/p0deje/Maccy/blob/master/README.md#usage) | 默认 Enter/点击将记录复制回剪贴板；等待 tooltip 可查看全文。 | 快速取用不需要常驻的复杂详情工具栏。普通文本可只读。 |
| [Alfred Clipboard History](https://www.alfredapp.com/help/features/clipboard/) | 主流程是搜索历史；保存为片段使用 `⌘S`；Return 自动粘贴可以关闭。 | 历史检索可以保持主位，低频动作无需铺在预览区。 |
| [Apple HIG — Materials](https://developer.apple.com/design/human-interface-guidelines/materials) | Liquid Glass 用于控件与导航的功能层，内容层使用标准材质；自定义玻璃效果应克制，避免分散对内容的注意。 | 右侧正文不再嵌套一个玻璃卡片；只给必要的小控件轻量承托。网页效果仍是近似。 |
| [Apple — Quick Look](https://support.apple.com/guide/mac-help/view-and-edit-files-with-quick-look-mh14119/mac) | 选中项目后按 Space 可在不开文件的情况下完整预览；可提供适合内容的旋转、标记或裁剪等操作。 | 大图可按需放大，操作按内容出现；不需要给所有类型复制一套通用工具栏。 |

以上“推论”是 Copiggy 的取舍，不是来源对我们布局的直接要求。

## 方案比较

| 方案 | 优点 | 代价与取舍 |
|---|---|---|
| 历史行内展开 | 内容与来源关系最直接，不新增侧栏 | 长文本、图片和结果会撑高行，切换记录时列表位置跳动，降低连续检索效率。 |
| 独立 Quick Look | 平时只有列表，完整内容在需要时出现 | 多一步打开/关闭；检查多条记录及增强前后对比需要反复切换上下文。保留为图片放大方式。 |
| 所有动作进入菜单 | 预览最干净，能力扩展容易 | 格式化等核心能力发现成本高。未来有多种动作时可补充，当前不作为唯一入口。 |
| 操作紧跟正文，图片角落放大 | 内容与动作关联直接 | 随正文长短和类型变化，操作位置不稳定。早期推荐，**已被用户的新布局偏好替代**。 |
| 上方内容、底部固定信息与操作 | 切换记录时底部位置稳定；内容保持主位，各类型结构一致 | 短内容会保留一些空白；纯文本底部只显示信息，不凭空增加操作。**当前采用。** |

## 当前采用的规则

1. 搜索位于整个面板上方；历史列表和预览在其下方对齐。初始仍只显示历史，明确选中后展开预览。预览固定高度与历史区域对齐，所有类型共用上方内容区和底部信息/操作区。
2. 预览没有类型标题、顶部工具栏或关闭叉。正文直接开始；`Esc` 保留返回列表的路径。
3. 上方内容区独立滚动，底部不随正文移动。普通文本与链接底部只显示字符数；受限内容可附范围信息，不生成操作按钮。
4. JSON 默认忠实展示原文；底部统一显示字符数、范围和格式化入口。显式点击格式化图标后才产生结果草稿，绝不在选择时自动改写。
5. 图片按原比例展示；底部统一区域显示尺寸、PNG 格式及放大按钮，图片角落不再重复放操作。不展示未实现的 OCR、压缩或去背景动作。
6. 只有已产生草稿时，底部才增加小型结果状态与查看原文、返回结果、放弃的控件胶囊。查看原文不改变确认对象；`↵` 始终明确提示使用结果。
7. 防误贴未生效与覆盖新内容等警告继续清晰可见。内容优先不等于隐藏风险状态。
8. 不使用内部切分线，不为右侧增加另一层材质背景。焦点轮廓、外缘高光与独立键帽仍保留。
9. 左下角防误贴改为直接开关，取消状态浮层：开启为盾牌勾，关闭为斜线盾牌，配合轨道及滑块位移。关闭后的未生效文字警告持续保留。
10. 受限记录的锁作为来源应用图标右上角小徽标，替代图标左侧独立锁；悬停与无障碍说明保留范围。守卫关闭时徽标呈琥珀色，并明确范围未生效，不能只靠颜色传达。

## 不变的行为边界

浏览、搜索、切换预览及生成草稿都不改当前剪贴板。无草稿时 Return 取用保存的原文；
有草稿时 Return 明确确认结果；双击历史行始终只取用该行保存的内容。
普通文本的旧“清理空白”入口在本轮界面中撤下，不因底层已有实现而保留无需求的操作区。
网页仅更新演示状态，系统写回、原生材质与跨应用行为仍分别以原生验证为准。

本决策替代旧静态稿及早期原型中的右侧类型标题、顶部处理/关闭行、普通文本清理入口和位于正文前的范围块。
其中统一固定底部进一步替代本次调研早期的“紧随内容”操作和图片角落按钮建议。
直接开关及来源图标锁徽标来自随后用户的具体布局偏好，不是上述竞品资料的结论。
